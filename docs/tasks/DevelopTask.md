### 0. 后续追加任务
### 0.1 列表时间分隔

分桶在列表投影的 `scanRows` 里完成，和收件账户小圆同一次扫描。分隔是另一种列表条目，由 `MailListPane` 画出。不写进 `Mail`，不进归约。第 5 项的长按和左右滑只绑邮件行。第 6 项只改这条线的最终样式。

验收：可见列表按时间档位分组，每组第一封上面有一条分隔线，线下靠左写档位名。

- [x] 一封信只进第一档：与今天同一自然周（周一到周日）为「本周」；否则仍在本月为「一周前」；否则仍在本年，写「十月」「九月」直到「一月」；更早写「2025年」「2024年」
- [x] 本周按自然周，跨月、跨年仍归「本周」。没有信的档位不占一条
- [x] 分隔不写进 `MailRowUi`。`LazyColumn` 用自己的 key 和 contentType，不参与行内测量和淡出
- [x] 多选、已读、删除仍只认邮件 id
- [x] 分桶跟现有行复用走同一分钟。不吸顶，不做离屏淡出

### 0.2 一周内的日期

只影响本自然周里、昨天及更早的行上时间和正文时间。今天两种模式都只显示时分。本周以外仍是月日。偏好写在本机显示设置，不进加密账号文件，切换时不收信。

验收：显示设置里可以改「一星期内的日期」。今天始终是时分。始终显示日期时，从昨天起是月日。相对关系时，从昨天起用「昨天」，同一自然周里更早的用周一到周日。

- [x] 显示设置增加这一类：始终按照日期显示，或按照相对关系显示
- [x] 相对关系从昨天开始：昨天；同一自然周里更早的显示周一到周日。昨天落在上一周时仍显示「昨天」，再早的跨周日期仍是月日。今天两种模式都只显示时分
- [x] 和列表分隔用同一个自然周（周一 0:00 到周日结束，设备时区）

### 0.3 正文长按选择

详情里的主题、寄件人、时间和正文可以长按，弹出系统的选择菜单。右下角按钮、全屏按钮和「这封邮件不在了」不参与选择。列表、分界线和清洗不动。第 5 项的内容横滑还没做，到时再和选择分开。

验收：长按正文出现复制和全选。手指没按住文字时，正文仍能上下滚。右下角三颗按钮仍能点。

## 2. 收信与本地库

有真实 IMAP 数据后再建持久化与同步；不建空 Repository。正文清洗归第 3 项，模型分类归第 4 项；本项只拉信头、落库、让列表读真数据，并让本机已读 / 归档与服务器对齐。

拆成两段：2.1 先能看见真信；2.2 再做增量保活与状态回写。

### 2.1 连通、落库与首拉

验收：登录后的账号能连上 IMAP，首拉信头进本地库，列表不再依赖样例邮件。

- [x] QQ 授权码、Gmail XOAUTH2 分别连上各自 IMAP（TLS）；Gmail 访问令牌过期时提示重登（`NeedsReauth`）；`AccountBook.updateGmailAccess` 供重登写回
- [x] 板块映射：收件箱 → INBOX；草稿 / 已发送 / 已删除优先按 `\Drafts`、`\Sent`、`\Trash`，对不上再试常见中文名；对不上显示空，不把信归错夹
- [x] 本地库存邮件头、本机已读、本机归档、同步游标（账号、文件夹、UID、UIDVALIDITY）；预留类型与标签字段，本阶段不写模型结果
- [x] 头字段：发件人、收件人、抄送、主题、时间、已读、附件标记、账号、文件夹、服务器邮件 ID
- [x] 某范围未拉过时：先出最近 7 天信头并可显示；再按「距今 30 天」与「全部邮箱合计 50 封」里更小的补历史；7 天已满 50 封则不补更早
- [x] 有真实账号后，列表与详情入口改订本地库 Flow；清掉样例信；会话归约仍只处理本机意图（筛选、多选、归档标记等）
- [x] IMAP、解析、写库不占主线程；同步失败不抹掉、不覆盖已有本地数据

### 2.2 增量、保活与本机状态

验收：库能增量跟上服务器；已读回写；归档只留本机且同步不把它塞回收件箱。

- [x] 用 UID + UIDVALIDITY 做增量，只取新信，不做每次全量重拉；UIDVALIDITY 变化时按该文件夹重建游标
- [x] 应用在前台且服务器支持时保持 IMAP IDLE；不支持或被系统挂起时改为 15 分钟定时拉取
- [x] 打开应用且有网时，只刷新当前列表范围（当前账号或全部邮箱 + 当前板块），不做全账号全文件夹大同步
- [x] 已读以本应用为准并回写服务器；一键已读只处理当前可见列表里的未读
- [x] 归档只改本机标记，服务器原文件夹不动；同步时已归档信不得重新出现在收件箱
- [x] 厂商自带分类（Gmail Social / Promotions、QQ 广告标记等）不参与判断，也不进后续提示词
- [x] 手指滑动或动画进行时，不把列表刷新抢到主线程上造成卡顿
- [x] 本期仍不做新邮件系统通知；后台取回即可

## 3. 正文与阅读

列表不等待正文。模型分类归第 4 项；删除的撤销、超时再写服务器归第 5 项。本项只把未处理邮件洗成文件，并让阅读能看。

拆成两段：3.1 先把正文落成文件，详情能看 Markdown；3.2 再做单个 WebView 与原版式。

### 3.1 拉取、清洗与落文件

验收：未处理邮件在后台写成安全 HTML 和轻量 Markdown；库只记路径和处理时间；点开未洗好的信优先处理这一封，列表仍可滑。

- [x] IMAP 只取正文的文本部分（`text/html`、`text/plain`），不把附件下进文件
- [x] 洗成安全 HTML：去掉脚本、内嵌框架、插件、表单、事件属性、`javascript:` 链接，以及用样式藏起来、字号为 0、靠与背景同色堆关键词的节点
- [x] 轻量 Markdown 只留段落、链接的可见文字和地址、列表文字、图片替代文字或「图片」占位；不嵌图片数据
- [x] 纯文本邮件生成简单 HTML，走同一套文件
- [x] 外链图片默认不请求，换成占位。清洗留「这一封允许加载」参数，默认关闭；打开它的按钮归 3.2
- [x] 文件落在 `files/mail/{账号}/{文件夹}/{邮件 ID}/body.html` 与 `body.md`。数据库只记路径和处理时间，不存正文
- [x] 后台洗未处理邮件。打开还没洗好的信时优先处理这一封，内容区给出平静的等待，列表仍可滑
- [x] 洗完后用 Markdown 纯文本开头填列表预览。洗完前预览继续为空，不回头改信头拉取
- [x] IMAP、清洗、写文件不占主线程；失败不抹掉已有文件和信头

### 3.2 阅读与单个 WebView

验收：默认用 Markdown 读；全局只有一个 WebView，空闲才创建；阅读中途就绪不换当前这封；拖分界线时 WebView 松手后再画。

- [x] 默认用 Markdown 阅读，不在进列表时创建 WebView。链接用系统浏览器打开
- [ ] 全局只有一个 WebView。空闲约半秒，且没有按压、惯性滑动、转场或分栏拖动时才创建。失败则继续用 Markdown，下次空闲再试
- [ ] 打开时 WebView 尚未就绪：这封保持 Markdown，中途就绪也不替换。已经就绪后换一封，才用 WebView 显示那一封的安全 HTML
- [ ] 点「按原版式查看」不必再等空闲，马上为当前这封创建并加载。加载中按钮进入进行中，避免连点出第二个实例。完成后按钮消失；失败则留在 Markdown 并告诉用户
- [ ] 编辑仍只说明尚未接入。删除沿用现在的本机删除；几秒内撤销、超时再写服务器归第 5 项
- [ ] 「这一封允许加载外链图片」的按钮放在这里，调用 3.1 的清洗参数
- [ ] 离开页面或宽屏关闭邮件时不销毁 WebView。进入后台过久或内存吃紧时可以释放，下次按空闲策略重建
