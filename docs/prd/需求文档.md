# Ainsmail 需求文档

版本：0.3  
日期：2026-11-16

## 前言

该项目开发的绝对目标是：

- **帧率与性能表现是绝对宗旨。** 必须消灭卡顿、发烫，任何行为都必须为帧率、处理器不发烫让路。
- **滑动、切换、交互必须流畅丝滑。** 加载、同步、清洗、分类、光效都没有交互丝滑重要。
- **视觉必须是现代的、交互动效、视觉效果完成度高的。** 可以有一点流光，但要克制。细高光、很慢的淡色变化可以出现在少数表面上；不要做成一排高饱和灯带，也不要让界面同时闪几种颜色。

## 开发要求：

- 项目已连接到GitHub仓库，内容更新后务必进行提交，方便后续错误处理与回退。

---

## 1. 产品目标

Ainsmail 是一个自用的 Android 原生邮箱。它接收并阅读用户自己的多个邮箱。

第一版要能完成这些事：

- 接入 QQ 邮箱（含 Foxmail 域名）和 Gmail
- 在一个邮箱里看信，或把多个邮箱的信合在一起看
- 在手机窄屏、折叠屏内屏（大约 1:1）、平板等宽屏上用同一套交互
- 把邮件洗成安全 HTML 和给模型用的轻量 Markdown，并落成本地文件
- 用 DeepSeek 给每封邮件做类型判断，并打 0～3 个标签
- 阅读时默认不付出 WebView 的启动成本

收信用 IMAP。写信的入口和 SMTP 的位置留出来，本期不把信发出去。

## 2. 已做的决定

| 事项 | 决定 |
| --- | --- |
| 收信 | IMAP over TLS |
| 发信 | SMTP 留到下次开发写信阶段。本期不发送 |
| QQ / Foxmail | 同一服务商。`@qq.com` 与 `@foxmail.com` 都登录 `imap.qq.com:993`，身份是完整邮箱地址，凭证是授权码 |
| Gmail | 优先使用 Google 登录。登录后读取用户头像，并用 OAuth 的 XOAUTH2 连接 IMAP 和 SMTP。不调用 Gmail 的 REST API |
| Gmail 自用授权 | 应用只给用户自己用，OAuth 同意屏幕发布为正式版，不做安全评估。OAuth 客户端不内置，由用户在设置里填写自己的 Google Cloud「Android」客户端 ID；同项目 Web 客户端密钥仅作换刷新令牌失败时的可选项 |
| 其他账号的头像 | 取不到头像的账号，由用户从本机相册上传。未上传时，用显示名生成纯色圆头像 |
| 界面技术 | Kotlin + Jetpack Compose |
| 正文清洗 | 用 HTML 解析器清洗（实现时用 Jsoup 一类库） |
| 正文放哪 | 清洗后的 HTML、Markdown 写本地文件。邮件头、已读、分类、标签、同步进度、归档标记放本地数据库 |
| 模型 | DeepSeek。密钥和模型名在应用设置里填写，密钥进系统密钥库 |
| 标签谁来改 | 模型只返回类型和标签名。池子的增减、衰减、升级、变陈旧由本地规则执行，设置里也可以手动改活跃池和待定池 |
| 时间长度 | 1.5 个月按 45 天，6 个月按 180 天 |

Gmail 的邮件通道与 QQ 一样，是 IMAP 收信、以后 SMTP 发信。Google 登录在这里的用途是头像和 OAuth 凭证。`https://mail.google.com/` 这一档权限同时覆盖 IMAP 与 SMTP，本期就把这档权限申请下来，SMTP 等写信时再使用。不使用 Gmail API 的只读或修改范围。

OAuth 客户端 ID 不写进安装包，也不进仓库。设置里由用户填写自己的 Google Cloud「Android」客户端 ID，连同刷新令牌放进系统密钥库，不写进日志。未保存客户端 ID 时，不能添加 Gmail。Android 客户端本身没有客户端密钥；若换刷新令牌失败，用户可在同项目另建「Web 应用」客户端，把 Web 客户端密钥作为可选项填进设置，不强制。

客户端取自 Google Cloud 里类型为「Android」的 OAuth 客户端。包名填本应用的 `applicationId`（`com.ainscel.ainsmail`），并登记当前安装包的 SHA-1 签名证书指纹（调试包与正式包指纹通常不同，都要能对上实际安装的那一份）。同意屏幕发布为正式版，范围包含 `openid`、`email`、`profile` 和 `https://mail.google.com/`。登录用 Google Play 服务的授权流程（`AuthorizationClient`），授权结束后回到本应用，不走系统浏览器本机回环，也不在应用内嵌 WebView 做登录。请求离线权限以取得刷新令牌，供 IMAP / SMTP 的 XOAUTH2 使用。每个人继续用自己的云项目。授权页上的「未验证的应用」是预期现象，确认后继续。头像和显示名用这次登录拿到的账号资料。

## 3. 术语

| 名称 | 含义 |
| --- | --- |
| 窄屏 | 窗口宽度不足以并排两栏的状态 |
| 宽屏 | 当前窗口够放下两栏的状态，包括折叠屏展开和横置平板 |
| 板块 | 收件箱、草稿、存档、已发送、已删除 |
| 聚合 | 多个账号的同一板块合成一个列表。顶部固定入口是全部账号，用户还可以自建聚合 |
| 未处理邮件 | 还没完成 HTML 清洗和 Markdown 提取的邮件。与未读不是一回事 |
| 类型 | 重点、验证、通知、推广、垃圾 |
| 标签 | 一封邮件上的 0～3 个短词 |
| 活跃标签 | 该类型下已经稳定的标签。按最近一次使用滚动计算是否变旧 |
| 陈旧标签 | 该类型下曾经稳定、已经超过 180 天没有新使用的标签。再次使用会回到活跃 |
| 待定标签 | 该类型下新出现、还在观察的标签 |

活跃和陈旧都是长期标签。分成两个池，是为了让模型先看见眼下还在用的词。

## 4. 邮箱接入

### 4.1 账号

第一版服务商只有 **QQ 邮箱** 和 **Gmail**。Foxmail 走 QQ 的服务器和授权码，界面上说明即可。账号模型保留服务商字段，方便以后加 Outlook、163 或自定义 IMAP。

QQ：邮箱地址 + 授权码。应用里写明授权码在 QQ 邮箱网页里打开 IMAP 后生成。QQ 没有可用的头像接口，添加账号时允许从本机选一张图；也可以稍后在设置里补。没选图时，用显示名做成纯色圆头像。

Gmail：先在设置里填写自己的 Android OAuth 客户端 ID，再走 Google 登录。成功后做两件事：

1. 读取账号头像并保存到本地，侧栏圆形头像用这张图
2. 取得 IMAP 与 SMTP 的 OAuth 凭证（含刷新令牌），收信用 IMAP XOAUTH2

用户之后可以用本机图片替换这张 Google 头像。客户端 ID、可选的 Web 客户端密钥、刷新令牌放系统密钥库，不写进普通配置或日志。设置里说明如何创建 Android 客户端（包名与 SHA-1），并说明 Web 客户端密钥仅在换刷新令牌失败时才需要。

显示名：Gmail 用 Google 账号名称；QQ 默认用邮箱 `@` 前的一段，用户可以改。

### 4.2 第一次拉取与以后的同步

列表不等待正文，更不等待模型。

某个范围还没拉过时：

1. 先拉**最近 7 天**的邮件头，拉到即可显示
2. 再往更早补。停止条件取范围更小的那一个：补到距今 **30 天**，或**所有邮箱加起来 50 封**，先到哪条停在哪条
3. 若 7 天里的信已经达到或超过 50 封，不再往更早补

例：

- 7 天共 20 封，第 8～30 天还有很多封：再补 30 封后停止，总数 50
- 7 天共 20 封，30 天内一共只有 35 封：把这 35 封补齐后停止
- 7 天已经有 80 封：停止，不再补历史

头信息至少包括：发件人、收件人、抄送、主题、时间、未读/已读、附件标记、所属账号、所属文件夹、服务器邮件 ID。

之后：

- 用 IMAP UID 与 UIDVALIDITY 做增量同步，只取新信，不每次全量重拉
- 应用在前台时，若服务器支持 IMAP IDLE，就保持这条连接，让服务器把新信推过来
- IDLE 被系统挂起或服务器不支持时，改为定时拉取。默认定时间隔 15 分钟
- 打开应用且网络可用时，刷新当前列表对应的范围，不做全账号全文件夹的大同步
- 网络、解析、写库都在后台。手指正在滑动或动画正在跑时，不抢主线程

已读以本应用的操作为准，并回写服务器。厂商自己的分类（Gmail 的 Social / Promotions，QQ 的广告标记）不参与判断，也不写进提示词。

本期不做新邮件的系统通知。后台把信取回来即可。

### 4.3 单邮箱、全部邮箱与自建聚合

- 选中某个账号：列表只含该账号
- 选中顶部的全部邮箱：各账号当前板块合成一个列表
- 选中自建聚合：只合成里面勾选的那些账号

聚合列表按时间从新到旧排列。每一行要能看出属于哪个账号。切换账号、聚合或板块时，列表换数据并回到顶部。宽屏右侧若开着一封不在新列表里的信，右侧回到空状态。

## 5. 布局

布局由**当前窗口宽度**决定。折叠、旋转、分屏时当场切换，并尽量保住正在看的那封信。

宽度同时放得下左栏约 280dp、右栏约 360dp 时用宽屏，否则用窄屏。到达这个限度之后仍然可以继续拖，只是阻力变大，松手弹回可阅读的宽度，不在边界上卡死。

### 5.1 窄屏

- 首页是邮件列表
- 点一封信进入内容页
- 内容页横向滑动回到列表
- 系统返回同样回到列表

### 5.2 宽屏

同一页左右分栏：

- 左：邮件列表，默认约占 34%
- 右：邮件内容，默认约占 66%
- 左栏比右栏窄
- 分界线可拖，比例记在本地
- 未选中邮件时右侧是空状态
- 在右侧内容上横向滑动：关闭当前邮件，右侧回到空状态

分界线拖动时：

- 右侧是 Markdown时：按新宽度正常重排
- 右侧是 WebView时：拖动过程中右侧画面保持不动，松手后再按最终宽度重绘
- 左侧列表可以跟着变宽

宽屏不增加第三栏。账号和板块仍然从左侧遮罩进入。

分界线是宽屏的底层布局，不专属于邮件。同一条分界、同一份比例，左栏和右栏分别放当前这一组页面。邮件是「列表 | 正文」。设置同样用它：栏目列表在分界线左侧，点开的栏目在右侧；还没点栏目时右侧是空状态。窄屏设置仍是两步，先栏目列表，再进入栏目内容。通知、隐私这类栏目可以先空着。填写 OAuth 客户端和大模型密钥是其中一个栏目。

### 5.3 左侧遮罩

窄屏和宽屏一样，从左侧滑出，盖在内容上，背后有遮罩。点遮罩或收起手势把它关掉。打开和收起用弹簧，拉过头有阻力，松手弹回。

遮罩内部分成两列。

**左列是头像列。** 只放圆形图像，不放文字。从上到下是三层：

1. 顶部固定：全部邮箱。圆里放一个聚合图标。点击后看所有账号。它不滚动、不参与排序、不能删除。
2. 中间滚动区：已登录账号的头像，以及用户自建的聚合。点击哪个就切换到哪个。长按后可以拖动排序，其他头像让位，松手弹簧落定。拖出这一列时有阻力，松手弹回列内。
3. 底部固定：设置按钮。不滚动，不参与排序。

滚动区底部的界限就是设置按钮的上沿。加号也在这个滚动区里，同样是一个圆，排在最后一个头像后面。点击加号，在「登录新邮箱」和「新建聚合」里选一个。

加号的位置：

- 它的自然位置在最后一个头像之后
- 自然位置还在底部界限上方时，加号跟在最后一个头像后面，一起排在内容里
- 自然位置会掉到界限以下时，加号停在界限上，不再往下走。上面的头像继续滚动，并从加号下层穿过
- 有头像穿过加号下层时，加号上沿出现淡化，把钻进去的头像渐隐掉。没有内容钻进去时，不放这层淡化
- 头像不满一列时，加号同样跟在最后头像后。这一列仍然可以拉动，松手回弹
- 头像超过一列、已经滚到末端，加号回到最后一个头像后面时，继续再拉仍可以动，阻力变大，松手回弹
- 滚到顶端继续拉，同样是阻力加回弹

全部邮箱这个圆的下沿：

- 有头像滚到它下面时，下沿出现淡化，避免和滚动中的头像叠在一起
- 停在顶端、没有头像被它挡住时，不显示这层淡化

自建聚合：起一个名字，勾选若干已登录账号。保存后，滚动区多一个圆，用这个名字生成纯色头像，参与排序。修改成员和删除放在设置里，不占用长按，长按只用来排序。

**右列是文字列。**

- 最上方：当前所选账号或聚合的名字
- 下面是板块，固定这五项：收件箱、草稿、存档、已发送、已删除

板块与服务器文件夹的对应：

| 板块 | 行为 |
| --- | --- |
| 收件箱 | IMAP 的 INBOX，并去掉已在本机存档的信 |
| 草稿 | IMAP 草稿夹。本期只阅读，不在这里写新草稿 |
| 存档 | 本机状态。用户把信归档后，它从收件箱消失，出现在这里。服务器上的原邮件先不动，同步时也不要把它重新放回收件箱 |
| 已发送 | IMAP 已发送 |
| 已删除 | IMAP 已删除 |

QQ 的文件夹中文名可能不同。用 IMAP 的特殊用途标记（`\Drafts`、`\Sent`、`\Trash`）对应，对不上时再按常见中文名匹配。对不上的板块显示为空，不把信归错地方。

## 6. 列表页

### 6.1 顶栏

第一行左侧是当前板块名，例如「收件箱」「已发送」。聚合时仍然只显示板块名。

右侧是两个常驻按钮和一个收纳按钮：

- 常驻：**筛选**、**一键已读**
- 收纳：**多选**、**搜索**、**写信**

筛选和底部类型胶囊是两层条件，可以同时生效。

筛选里有两组：

- 已读状态：不限、已读、未读
- 标签：分成活跃、陈旧、待定三块，每块里再按类型分组。选中的标签留下带这些标签的信

未选任何标签时，不按标签限制。一键已读只处理**当前列表里**的未读，类型胶囊和筛选正在生效时，不改到列表以外的信，并回写服务器。

搜索入口先留着。点开后说明搜索还没启用，本期不实现搜索算法。

写信入口打开占位页，说明发信尚未接入。多选的入口还有长按松手，见第 7 节。

### 6.2 邮件行

每一行从左到右：

```text
[圆形头像]  姓名  标签 标签 标签          时间
            标题，更早结束，末端淡出
            内容一直铺到右缘，末端淡出
```

**头像。** IMAP 拿不到寄件人头像。用寄件人名称生成一个纯色圆：名称字符串的哈希映射到 HSL 的色相，饱和度和亮度收在稳重区间，避免每一行都是荧光色。圆内放名称的前两个字；拉丁字母放前两个字母。多出来的不显示，也不加省略号。

**第一行。** 左侧是寄件人姓名，左对齐。右侧是时间，时间左边隔一点空间放下这封信的全部标签（0～3 个），标签从右贴着时间开始向左排列。姓名太长时压缩姓名，右端淡出，不用省略号。标签和时间保持完整。

标签的样子表示它在池子里的身份：

| 身份 | 样子 |
| --- | --- |
| 活跃 | 蓝色描边，填充从轻，不做成实心色块 |
| 陈旧 | 同一形状，颜色改为低饱和、偏灰的蓝 |
| 待定 | 虚线边框 |

**第二行。** 标题。可用宽度比第三行短，更早截断，截断处淡出，不用省略号。这样标题在视觉上收得更紧，和正文拉开。

**第三行。** 内容预览，从左铺到这一行的右缘。右缘用淡化渐变消失，不用省略号。预览取 Markdown 的纯文本开头；还没有 Markdown 时，用邮件头里的预览文本。

未读和已读要能分开。已读不能只靠把字弱化到看不清。

列表是虚拟列表。行里不放 WebView。头像颜色本地计算，不为此发网络请求。

### 6.3 类型胶囊

只在**收件箱**显示。草稿、存档、已发送、已删除不显示。那些信仍然会在后台被分类。

胶囊是一条偏扁的悬浮长条，列表底部留出空档，最后一行不被挡住。里面的类型是：重点、验证、通知、推广、垃圾。不把「全部」写成其中一格。类型多到放不下时，胶囊内部可以横向滑动，两端过滑回弹。

胶囊左侧有一颗圆球，直径等于胶囊高度，与胶囊垂直居中，贴在胶囊左边。

- 点这颗圆球：当前类型回到全部，整条类型胶囊收进圆球里。圆球的左边缘停在原地，横向稍微变长，里面出现文字「分类」
- 再点这颗写着「分类」的短胶囊：短胶囊缩回圆球，类型胶囊展开。展开本身不改变「全部」，直到点中某一个类型
- 收起和展开用弹簧，胶囊像被收进球里，而不是突然消失

打开收件箱时默认是全部，也就是收起态：左边是「分类」，类型胶囊不展开。

尚未分类的信在全部里可见，带一个安静的「分类中」。某个具体类型下面不出现还没分类的信。已归档的信不出现在收件箱的任何类型里。

## 7. 手势

总原则：拖动和滑动到尽头时用阻力和回弹，尽量不设硬停止。松手后的落点用弹簧，不使用生硬的匀速。

| 场景 | 手势 | 结果 |
| --- | --- | --- |
| 列表，普通横向滑 | 横滑 | 打开或收起左侧遮罩 |
| 列表，长按后松手 | 按住一封信，时间到了就松开 | 进入多选 |
| 列表，长按后向左滑 | 接着向左滑 | 露出回复、删除 |
| 列表，长按后向右滑 | 接着向右滑 | 露出添加标签、归档 |
| 头像列 | 长按头像再拖 | 给账号和自建聚合排序 |
| 窄屏内容页 | 横滑 | 回到列表 |
| 宽屏右侧内容 | 横滑 | 关闭当前邮件，右侧变空 |
| 宽屏分界线 | 拖动 | 改变左右宽度。越过舒适范围时有阻力，松手弹回 |

纵向滑动是滚动。横向位移明显大于纵向时，才判成横向。

### 7.1 列表横滑与遮罩

手指在列表上、且不是长按之后的那一下：向右滑打开遮罩，向左滑收起。遮罩已经打开时，在遮罩上向左滑也收起。拉过展开或收起的位置时有阻力，松手弹到开或关。

已经进入长按的那一行，后续横向移动只驱动快捷操作，不再带动遮罩。

### 7.2 长按的两个分支

按住一行，达到系统长按时间后，该行用大约 150ms 的过渡变色。

然后：

1. **几乎没移动就松开**：进入多选，这一行变为已选
2. **接着横向滑动**：进入这一行的快捷操作，不进入多选
3. **接着纵向滑动**：取消长按，颜色恢复，列表照常滚动

长按成立本身不震动。

### 7.3 多选

复选框从每一行左侧渐变出现，透明度和宽度一起变化，文字不被突然挤跳。

- 手指在复选框这一列上滑动，滑过的行变为选中。滑过已选中的行不会取消
- 手指在复选框以外滑动，不连选，列表正常滚动
- 点复选框可以单独选中或取消
- 系统返回退出多选，选择清空，复选框渐隐

多选态顶栏显示已选数量，并提供：

- 删除
- 更改分类（五类里选一个，不重新请求模型）
- 添加标签
- 归档
- 取消

其余批量动作以后再加。删除和归档都先从列表拿走，几秒内可撤销，超时再真正执行。删除会把信移到已删除，并同步服务器。归档只改本机标记。

添加标签时，从已有标签里选，也可以手输新词。已有标签按第 10 节刷新所在的池；新词进入这些邮件各自类型的待定池，次数从 1 开始。

### 7.4 行内快捷操作

长按成立后：

- 向左滑，按顺序露出 **回复**、**删除**
- 向右滑，按顺序露出 **添加标签**、**归档**

一档对应一个按钮完全露出。两个方向各有两档。按钮都露出之后仍可继续滑，超出最后一档的距离越大，阻力越大。

松手：

- 还没到第 1 档的一半：弹回收起
- 过了某一档的完成位置：弹到该档并停住，按钮可点
- 滑进最后一档以外的阻力区：弹回最后一档

滑到某一档不会自动执行。点按钮才执行。点这一行的空白处或反向滑回，把行收起。

回复打开写信占位页，并带上这封信的信息，本期不发送。删除、归档的撤销与多选相同。添加标签与多选里的添加标签用同一套选择和入池规则。

### 7.5 震动

只在行内快捷滑动里震动，手感要像拨开一个很轻的拨片：短、轻、快。

- 横向滑动刚刚被确认时震一次
- 每一档第一次完全露出时震一次
- 同一档不重复震
- 阻力区、回弹、遮罩、多选、排序都不震

单次约 8～15ms、低振幅。优先使用系统轻触感。没有振幅控制时用一次极短震动，不用默认长震动。

### 7.6 内容页横滑

窄屏：内容上的横向滑动回到列表，和系统返回是同一个退出。

宽屏：右侧内容上的横向滑动关闭当前邮件，右侧变为空状态，列表选中态去掉。

从屏幕最边缘起滑时，让给系统返回。系统返回在窄屏回到列表，在宽屏关闭当前邮件。

## 7.7 宽屏分界线拖动

- 宽屏分界线默认是左侧约占40%，右侧约占60%。
- 当用户拖动时，左侧内容占比最大到60%，最小到35%
- 当用户向两侧拖动超过限度后，仍然可以拖动，但是会逐渐施加阻力。用户松手后分界线会回弹。
- 当用户向左拖动超过限度时，左侧内容不再缩窄，宽度固定在此时的宽度。然后用户继续拖拽分界线时，分界线会向左覆盖掉左侧一部分内容，松手后回弹回去。向右超过界限时也一样，右侧和左侧内容宽度都固定，但是可以继续向右拖动覆盖右侧内容，松手会回弹会限度位置。
- 右侧正开着一封邮件时，向左超过最小占比后如果手指继续滑到接近屏幕左边缘，阻力取消，分界线收到屏幕最左侧，邮件内容全屏。右侧没有打开邮件时，不会进入这个全屏。
- 宽屏正文右上角有全屏按钮，点击后是同一次收拢：分界线移到左边缘，邮件内容全屏。已经全屏时再点，分界线回到刚才的比例。

## 8. 正文清洗与存储

每封尚未处理的邮件，在后台做成两份结果。列表不依赖它们先完成。

### 8.1 安全 HTML

保留段落、标题、列表、表格、引用、链接、图片位置、粗体和斜体。

去掉脚本、内嵌框架、插件、表单、事件属性、`javascript:` 一类链接，以及会加载外部程序或藏起大段追踪文字的样式。用样式藏起来、字号为 0、靠与背景同色来堆关键词的节点，HTML 和 Markdown 里都去掉。

外链图片默认不请求，留下占位，用户可以选择加载这一封的图片。

纯文本邮件由文本生成一份简单 HTML，走同一套文件和显示路径。

### 8.2 轻量 Markdown

给人临时阅读，也给模型。只保留：

- 段落文字
- 链接的可见文字和地址
- 列表文字
- 图片的替代文字或「图片」占位

不嵌入图片数据，也不追求还原栏位和颜色。

### 8.3 文件位置

```text
files/mail/{账号}/{文件夹}/{邮件 ID}/body.html
files/mail/{账号}/{文件夹}/{邮件 ID}/body.md
files/account/{账号}/avatar
```

数据库记录文件是否写好、路径和处理时间，不把 HTML 或 Markdown 放进数据库字段。账号头像是图片文件。寄件人的纯色头像不落图片，显示时按名称现算。

用户打开一封还没洗好的信时，后台立刻处理这一封，内容区给出平静的等待，列表仍然能滑。

## 9. 阅读与 WebView

全局只有 **一个** WebView。切换邮件时复用它，不按邮件创建，也不在列表里创建。

### 9.1 什么时候创建

打开应用、进入列表时不创建 WebView。同时满足下面几点才在后台创建：

- 没有手指按下
- 列表不在惯性滑动
- 没有页面转场或分栏拖动

空闲大约半秒再创建。失败则继续用 Markdown，下次空闲再试，不立刻循环重试。

用户点了「按原版式查看」时，不必再等空闲，马上为当前这封创建并加载。

### 9.2 当前这封信用什么显示

| 情况 | 显示 |
| --- | --- |
| WebView 还没就绪，用户打开了邮件 | Markdown |
| 打开时尚未就绪，随后才创建完成 | 这封保持 Markdown，不在阅读中途替换 |
| WebView 已就绪，用户改看另一封 | WebView 显示那一封的安全 HTML |
| 正在看 Markdown，用户点右下角按钮 | 立刻加载，完成后替换当前内容 |

WebView 显示的是清洗后的 HTML 文件。离开页面或宽屏关闭邮件时不销毁实例。进入后台过久或内存吃紧时可以释放，下次按空闲策略重建。正开着的那封在自动路径下不中途替换。

### 9.3 Markdown 上的按钮

Markdown 显示时，邮件内容页右下角有一列圆形浮动按钮。直径与列表底部的分类胶囊高度相同，最下面一颗和分类胶囊处在同一画面高度。从下往上是：编辑、删除、按原版式查看。

编辑本期还没接上，点了只说明尚未接入。删除把当前这封移到已删除，几秒内可撤销，并关掉正文。

按原版式查看：

- 点下去就为当前这封加载 WebView
- 加载中按钮进入进行中状态，避免连点出第二个实例
- 完成后按钮消失，内容换成安全 HTML
- 失败则留在 Markdown，并告诉用户这次没有换成原版式

邮件里的链接用系统浏览器打开。

## 10. 分类与标签

每封邮件在 Markdown 准备好之后，交给 DeepSeek **一次**。这一次同时判断类型和标签。

设置里没有填写密钥时，不请求模型，信保持未分类，阅读和列表照常。

### 10.1 发给模型的内容

- 轻量 Markdown 正文
- 发件人、收件人、抄送、主题、时间
- 五个类型各自的活跃池、陈旧池、待定池
- 允许新增标签：允许

提示词按类型分段，让模型先判断类型，再把注意力放在该类型的池子上。结构如下：

```text
重点分类中——活跃标签池:[...]、陈旧标签池:[...]、待定新增标签池:[...]
验证分类中——活跃标签池:[...]、陈旧标签池:[...]、待定新增标签池:[...]
通知分类中——活跃标签池:[...]、陈旧标签池:[...]、待定新增标签池:[...]
推广分类中——活跃标签池:[...]、陈旧标签池:[...]、待定新增标签池:[...]
垃圾分类中——活跃标签池:[...]、陈旧标签池:[...]、待定新增标签池:[...]

先判断这封邮件属于哪一类。
然后优先使用该类的标签池。
该类没有合适标签时，可以使用其他类里已有的标签，必须沿用原来的词，不要改成近义词。
所有类的池子里都没有合适标签时，才新增标签。
每封邮件给出 0～3 个标签。
```

例如重点下面可以有「AI」「同事」「公司」，推广下面可以有「Steam」「推特」。模型看到一封推广信时，先在推广这三段池子里找，而不是在一整份长词表里找。

正文过长时截断后再发送，并注明已截断。默认上限约 6000 个汉字量级的正文。主题和收发件人完整保留。

不发送：安全 HTML、原始 MIME、附件内容、授权码、密钥、其他邮件、厂商分类。

### 10.2 类型

| 类型 | 含义 |
| --- | --- |
| 重点 | 确实需要阅读的信，以及套不进另外四类的信 |
| 验证 | 验证码、登录验证、确认码 |
| 通知 | 异地登录、账号消费、账单、安全提醒 |
| 推广 | 订阅周报、营销、活动推广 |
| 垃圾 | 可以确定的诈骗、无意义邮件 |

套不进后四类时归入重点，这条写进提示词。请求失败、超时或返回了五类之外的值时，信保持未分类并稍后重试，客户端不擅自标成重点。

### 10.3 一封信上的标签

每封信 0～3 个。模型多给的，只取前 3 个。一个都不给是合法结果，不为了凑数制造标签。

比较名字之前去掉首尾空白。同一封信上的重复标签合并。

邮件上立刻保存返回的标签，包括第一次出现的新词。列表按第 6.2 节的三种样子显示。

一个标签词只归属一个类型的一个池。提示词把它放在所属类型下面，不在其他类型里再抄一遍。模型可以跨类型沿用这个词。沿用时刷新它自己所在的那个池，不在当前类型再造一个同义词或另一份拷贝。

### 10.4 池子规则

池子按类型分开，五个类型各有活跃、陈旧、待定。所有账号共用这套池，不按账号复制。

首次安装时，在重点的活跃池放入起点：AI、同事、公司。其他类型从空池开始。这些起点可以在设置里删掉。

**活跃 → 陈旧（滚动）**

- 标签每次被新邮件使用，就把「最近使用时间」更新为现在
- 从最近使用时间起连续 180 天没有新邮件使用，移入**同一类型**的陈旧池
- 手动加入活跃池时，最近使用时间记为加入那一刻

**陈旧 → 活跃**

陈旧标签再次被一封新邮件使用，立刻回到同一类型的活跃池，并重新开始 180 天滚动。

**待定池**

新词在所有类型的三个池里都不存在时，进入**这封信所属类型**的待定池。每条记录：

- 出现次数
- 上一次触发时间
- 平均更新间隔：相邻两次触发的时间差的平均值

规则：

1. 第一次出现：次数记为 1，记下时间。没有平均间隔
2. 次数仍为 1 时，若 45 天内没有再次出现，从待定池删除
3. 再次出现：次数加 1，更新平均间隔，并刷新上一次触发时间
4. 次数大于或等于 2 时，若距离上一次触发已经超过「平均间隔 + 5 天」，次数减 1。减完后把上一次触发时间改成这次衰减的时刻，避免同一次沉默被连续扣掉
5. 次数是 1 时，只用第 2 条，不用间隔去减
6. 次数加到 4 的那一次，立刻进入同一类型的活跃池，并开始滚动计时

衰减后若回到 1，从衰减那一刻重新计算 45 天。次数不会被间隔规则减到 0。

自动从待定池消失后，已经写在旧邮件上的词还留着，继续用虚线样式。以后同名标签再次进入某个池，样式改成那个池的样子。

示例：

- 第 0 天，重点里第一次出现「课程」，次数 1。直到第 45 天没有第二封，则从重点的待定池删除
- 第 10 天又出现，次数 2，间隔 10 天。静默阈值是 15 天
- 再过 15 天没有出现，次数变为 1，并从这一天重新计算 45 天
- 若某一次把次数加到 4，当天进入重点的活跃池

模型沿用了其他类型已有的词时，按那个词自己的池更新：活跃就刷新滚动时间，陈旧就回到活跃，待定就按上面的次数加一。不在当前类型新建近义词。

检查衰减和过期的时机：应用启动、每次同步结束、每天至少一次。

### 10.5 设置里的标签管理

设置中按类型管理标签池。每个类型都能看到活跃、陈旧、待定。

- 活跃池：可以手动新增和删除
- 待定池：可以手动新增和删除。手动新增时次数记为 1，之后走自动规则
- 陈旧池：只展示。进入和离开由第 10.4 节的规则决定，不在这里手动新增

从活跃池或待定池手动删除后，池里去掉这个词，已经打在邮件上的同一个标签也去掉。这和自动过期不同：手动删除表示用户不要这个词。

### 10.6 请求怎么跑

- 一封信一次请求，排队执行
- 同时最多 2 个，默认 1 个
- 用户刚点开、还没有 Markdown 的那一封优先
- 结果写回后，列表上的类型和标签就地更新，不打断滚动位置
- 接口做成可替换的。本期请求发往 DeepSeek 的对话接口，默认模型用实现时 DeepSeek 官方的通用对话模型，不把推理模型当作默认。设置里可以改模型名

模型只返回一个类型和 0～3 个标签名，不返回池子的增删指令。

## 11. 视觉、流畅与回弹

### 11.1 视觉

界面要现代、干净、耐看。

流光只用在少数位置：顶栏、侧栏里当前选中的头像、底部类型胶囊、按下时的高亮。表现形式是低对比的高光缓慢滑过，或表面有很淡的色相变化。同一时刻只走一层，速度慢，幅度小。

列表行和正文保持安静，方便扫读。不在每一行上加彩虹边缘，不用高饱和颜色循环，也不把光效铺满整个屏幕。

寄件人头像的色相可以各不相同，但饱和度要收住，让它们像一套纸签，而不是一排发光二极管。

### 11.2 流畅

- 列表快速滑动时，新行出现不卡顿。清洗、同步、模型、WebView 创建、头像淡化都不能把滑动做顿
- 窄屏进出内容、宽屏换一封信、遮罩开合、胶囊收进圆球，动画连贯
- 长按变色、复选框、行内滑动、头像排序，都跟手
- WebView 的创建和 HTML 加载不放在手指移动的那几帧里
- 主线程上不做 IMAP、HTML 清洗、Markdown 生成、模型请求、大文件读写
- 拖动分界线时，Markdown 可以重排；WebView 松手再画

常用旗舰机和普通中端机都应维持设备自身的刷新率。

### 11.3 回弹

这些地方都用弹簧，尽头是阻力而不是硬墙：

- 邮件列表和正文的过度滚动
- 头像列，包括头像不满一列的时候
- 遮罩拉开和收起
- 行内快捷操作拉过最后一档
- 类型胶囊内部横滑，以及胶囊收进圆球、圆球展回胶囊
- 宽屏分界线拖过舒适宽度
- 头像排序时拖出头像列

档位、最小栏宽、加号停在设置按钮上方，这些是松手后要弹回去的落点，不是手指还按着时就推不动的墙。

## 13. 第一版验收

- 能添加 QQ 邮箱和 Gmail。Gmail 使用设置里填写的 Android OAuth 客户端 ID，经 Play 授权回到应用后得到头像与刷新令牌，并用 IMAP 收信；未填写客户端 ID 时不能添加 Gmail。QQ 可以上传头像
- 第一次同步先出现最近 7 天的信，再按 30 天和全部邮箱合计 50 封里更小的范围补历史
- 应用在后台会定时补新信；服务器支持时能用 IMAP IDLE 收新信
- 头像列顶部固定全部邮箱，下面是可排序的账号和自建聚合，加号按「没到底就跟随、到底就固定并让头像从其下穿过」工作，底部是设置
- 右列显示当前名字和五个板块。归档后的信离开收件箱，出现在存档，同步不会把它放回
- 窄屏列表进内容；宽屏左窄右宽，分界线可拖，拖过限度会回弹；WebView 在松手后才重绘
- 列表行是头像、姓名加全部标签、时间、更早省略的标题、右缘淡出的预览
- 活跃、陈旧、待定三种标签样式能区分
- 收件箱底部胶囊不含「全部」。圆球能把胶囊收成「分类」并回到全部，再点可以展开
- 长按松手进入多选，并能删除、改分类、加标签、归档
- 向左滑是回复和删除，向右滑是添加标签和归档；过滑有阻力，档位有轻而短的触感
- 筛选能按已读/未读和三个池的标签过滤。搜索入口在，搜索本身未启用。写信入口在，发信未启用
- 未处理邮件生成安全 HTML 和轻量 Markdown 两种文件
- WebView 只有一个，空闲时才创建；没就绪时用 Markdown；自动改用 WebView 发生在改看另一封时；右下角按钮可以立刻换当前这封
- 链接用系统浏览器打开
- 每封信最多请求一次 DeepSeek，密钥来自设置。类型是五类之一，标签 0～3 个
- 提示词按类型列出三个池，并要求先用当前类型、再用其他类型的原词、最后才新增
- 待定标签按 45 天、次数、平均间隔加 5 天、满 4 次进入活跃池这些规则变化
- 活跃标签按最近使用滚动，180 天没用则变为陈旧；陈旧标签再被使用则回到活跃
- 设置里可以按类型手动增删活跃池和待定池
- 快速滑动时，后台工作和光效不会把列表做顿

## 14. 实现时的模块划分

| 模块 | 职责 |
| --- | --- |
| 账号 | QQ 授权码、用户填写的 Google Android 客户端 ID（及可选 Web 密钥）、Play 授权登录与头像、IMAP/SMTP 凭证、本机上传头像、密钥库 |
| 同步 | 7 天首拉、30 天或 50 封的补齐、IDLE、15 分钟定时、已读回写 |
| 仓库 | 邮件头、分类、分类型标签池、归档标记；HTML、Markdown 和账号头像文件 |
| 清洗 | 安全 HTML、轻量 Markdown |
| 模型 | DeepSeek 单封请求、按类型组织的提示词、队列、失败重试 |
| 标签池 | 分类型的待定、活跃、陈旧转移；设置里的手动增删 |
| 界面 | 窄屏与宽屏、遮罩头像列、五板块、列表行、类型圆球与胶囊、设置 |
| 手势 | 遮罩、长按分支、多选、左右快捷操作、头像排序、分界线、过滑回弹 |
| 阅读 | Markdown、单个 WebView、系统浏览器打开链接 |
| 写信 | 本期只有入口和占位页 |
