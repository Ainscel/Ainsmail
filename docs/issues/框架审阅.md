# 框架审阅

版本：0.2
日期：2026-11-15
范围：test 分支的页面骨架。这一版把 0.1 里要改的结构债收掉了。样式、动效、IMAP、模型分类仍按「还没做」对待。

决策记录在 [框架问题.md](框架问题.md)。那里写明留着的事，不要再开一遍。

---

## 结论

地基可以接着做功能。审阅里会放大的问题，能在框架阶段收口的已经收口。不该提前做的手势已经删掉，没有留下半成品监听。

宽屏空右栏仍只有详情和设置两种。第三种左栏出现时再改 `TwoPaneStrategy`，现在不做抽象。

---

## 已经收口

1. 根界面和列表拆开订阅。`MailboxChrome` 只有范围、板块、账号和提示。`MailboxList` 放筛选和行。`MailApp` 只读 `chrome`。账号的 id 和名字没变时，投影沿用上一份账号列表。改已读、改筛选不会换这份列表，也不会重组遮罩。
2. 正文和回复主题由 `MailboxViewModel.detail` / `subjectOf` 在组合里取出。这两次读取订阅的是信件本身，不订阅筛选和多选。打开哪封信只在返回栈里，不写入会话。页面只收 `MailDetailUi` 或主题字符串。
3. 列表、正文、遮罩上的横滑已删除，包括 `horizontalDragOrScroll`，以及遮罩上为横滑准备的拖动和阻力。遮罩仍由标题、设置按钮、点空白和返回键开关。分界线拖动留下，它是宽屏布局，不是列表手势。长按、横滑快捷操作等需求第 7 节再整段设计。
4. 登录、新建聚合、按原版式查看、写信这些还没做的提示改为 `UnavailableHint`，只在界面弹出。归约里的 `Notice` 只保留删除、归档和标签失败。
5. `avatarColor` 挪到 `ui.shell`。壳层不再依赖列表包。
6. 分栏比例用 `rememberSplitFraction`。恢复存档时夹进 0.35 到 0.60，默认 0.40。根组合里不再每次校正，也不再特判旧的 0.34。

归约测试覆盖了「已读之后 chrome 相等，并且账号列表是同一个实例」。

---

## 明确不改

- `TwoPaneStrategy` 仍直接选择 `EmptyDetail` 和 `SettingsPaneEmpty`。第三种左栏再改这一处。
- `MailListPane`、`AvatarScroller` 超过 80 行。等做对应界面时再拆，不单开一轮。
- 不建只有一个实现的 Repository。样例数据仍由 `MailApp` 传入。
- `Mail.body` 仍是内存占位。列表投影不准读它。
- 自建聚合不预留空类型。
- 标签衰减写成 `TagCatalog` 旁边的纯函数，现在还没写。
- 授权码和刷新令牌以后放进同一份加密文件的另一段，不加进现在的 `Secrets`。
- 撤销只恢复文件夹和归档标记，并且立刻改内存。超时后再同步服务器，等有写回再加。
